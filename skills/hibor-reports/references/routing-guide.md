# 场景路由与能力边界

## 一句话分工

**研报文本走 `hibor`，市场数据走 `westock-data`，向量入库走 `push`（WeKnora），本地知识库问答走 QMind。**

| 用户在问 | 用什么 | 不要 |
| --- | --- | --- |
| 「紫金矿业最近有什么研报」「找几篇铜行业的报告」 | `hibor stock list/fetch`、`hibor industry list/fetch` | 不要用 web_search 找研报标题，不要用训练数据编标题 |
| 「这些研报讲了什么」「把研报收进知识库好让我问」 | `hibor fetch` → `hibor push --kb …` | 不要自己写脚本读 Markdown 再上传 |
| 股价、K 线、市值、涨跌幅、成交量 | `westock-data`（`quote` / `kline`） | 不要用 hibor —— 它没有任何行情能力 |
| 财报数字、ROE、估值、分红、股东 | `westock-data`（`finance` / `technical` / `dividend` …） | 不要从研报摘录里手算比率 |
| 券商研报的**评级与目标价**字段 | `hibor` 的 `items[].rating`（站点有就带，常为空）；研报正文里的观点见抓下来的 Markdown | 不要把摘录里的评级当实时评级 |
| 上市公司公告、新闻快讯 | `westock-data`（`notice` / `news`） | hibor 抓的是研究报告，不是公告流 |
| 已经入库的内容问答 | WeKnora 检索 / QMind | 不要为了回答重复抓取 |

## hibor 能做到什么

- 按个股简称/代码在慧搜检索，或按行业大类/细分行业浏览列表页；
- 判相关性（四道闸）、去重（SQLite）、把**详情页正文摘录**存成带 frontmatter 的 Markdown；
- 把这些分组目录推到 WeKnora 知识库并等解析结果；
- 报告状态与失败明细；体检（profile / 登录态 / 限流）。

## hibor 做不到什么（碰到就如实说，不要绕）

| 需求 | 现状 | 该怎么回应 |
| --- | --- | --- |
| 下载 PDF 原文 | 不支持，也不该加 —— 站点有积分/登录门槛，抓 PDF 属于绕过 | 说明只抓文字摘录；要原文请用户自己在浏览器下载 |
| 整份研报全文 | 只有 `.abstruct-info` 的摘录（通常几百到一两千字） | 别说「全文已入库」；说清是站点给的摘录 |
| 图片型/扫描版报告正文 | 记为 `empty`，不落文件 | 说明这篇没有文字正文 |
| 历史全量回溯（如"近三年所有有色研报"） | 能跑但很慢，且受站点节奏限制 | 先小窗口 `list` 探量，再和用户确认要不要放大 `--days`/`--max` |
| 定时任务 / 增量监控 | 无调度器，靠外部计划任务重复调用 | 给出一条可复用的 `fetch` 命令，或让用户接 cron/计划任务 |
| 多标的并行抓取 | profile 只能被一个进程持有 | 串行跑；`status`/`push` 这类不开浏览器的可以并行 |
| 非研报内容（公告、新闻、路演纪要） | 慧博上有但本 CLI 没做入口 | 说清能力边界，换 westock-data 或让用户决定 |

## 与其他技能的配合顺序

一个典型请求「把紫金矿业最近一个月的研报入库，然后告诉我主要观点」：

1. `hibor stock list 紫金 --days 30 --max 20` —— 先看命中篇数与标题是否合理；
2. 简称歧义或命中太少 → 换代码 `601899`，或 `--scope abstract`（并检查 stderr 的丢弃原因）；
3. `hibor stock fetch …` —— 落盘，读 `data.folder` 与 `saved_paths`；
4. `hibor push --kb <库> --stock 紫金 --dry-run` → 向用户确认 → 去掉 `--dry-run`；
5. 读本地 Markdown（或入库后用 WeKnora 检索）总结观点；
6. 用户接着问股价表现 → 切 `westock-data`，不要试图从研报摘录里推断行情。

## 什么时候**不该**用本技能

- 用户只要一个数字（市值、涨幅、EPS）→ `westock-data`；
- 用户问的是港股/美股/基金的公开信息 → 本技能只覆盖慧博上的中文研究报告，且不保证该市场覆盖；
- 需要可复现的引用（页码、原文段落）→ 摘录不够，说明限制；
- 站点已被限流（退出码 4）→ 停止并告知用户，不要换关键词继续打。
